# Local Three.js preview

Run `python <skill>/scripts/animation.py editor [project.json] --open`, or double-click `启动编辑器.cmd` on Windows. The default page is the clean review interface on `http://127.0.0.1:8766`; the server must remain running. Use `--port` for another port and `--workspace` for the editor workspace. The launcher can reopen an existing server at the default port.

The server binds only to loopback. Bundled Three.js modules load locally; no CDN, cloud upload or API key is needed. Blender and Python rendering dependencies still need to be installed, as reported by `animation.py doctor`.

## Display settings

Both review and authoring pages start in dark mode. Open **Display settings** in the header to select Dark, Light or System and English, Simplified Chinese or Traditional Chinese. When creating a review, the agent sets `ui_language` from the user's current conversation language and writes its question, title and control/display labels in the same language. The resulting `context_lang` URL parameter supplies the automatic interface default before first paint. The browser's language list is used only without this context, then English is the fallback. A saved manual choice takes precedence over the automatic default. The browser remembers manual choices for this local server; a different browser or server port has its own preferences. Blocked browser storage does not prevent using the controls, but choices may not survive a reload.

Language changes update interface labels, status messages, tooltips and accessibility text in place. Pending parameter edits, notes, surface marks, the current frame and camera are retained. Project names, agent questions, object IDs, user notes and diagnostic content supplied by a project keep their original text. The theme controls interface surfaces and viewport helpers; it does not recolor the asset, edit scene lighting or change final Blender renders. A project camera retains its authored background.

The interface uses local message dictionaries with English fallback rather than an online translation service. See [interface-localization.md](interface-localization.md) to maintain or add languages.

The review workspace groups the model, view controls, inspection tools and playback into one canvas board. View controls sit above the model; the inspection tool row and animation playback sit together below it. Findings remain beside the adjustment question in the separate adjustment panel. On narrow screens that panel opens below the board. Surface picking keeps the user's current panel and note expansion state; it must not open feedback automatically while the user is aiming a second point.

Inspection steps, unsuccessful-pick messages and snap candidates appear in a persistent overlay inside the model view. Updating or dismissing this overlay does not change the canvas size or move the model. The overlay does not intercept surface picks. Buttons and disclosure controls with help text use shared tooltips on pointer hover or keyboard focus; their text follows the current language and control state. Parameter and playback sliders fill the track up to their current value, including values changed by playback, reset or numeric entry.

## Default review view

The agent creates an adjustment request before asking the user to participate. The page shows the agent's question, relevant story segments, a large preview, and only the request's permitted controls. It focuses the relevant objects, camera and source frame. Orbit, playback and scrubbing help inspect the scene; selection can identify the object referenced by a note. These viewing actions do not authorize unrestricted model edits.

Model, motion, camera and delivery use the same underlying project and preview. What changes between stages is the current question, focus and permitted adjustments. A model review may expose proportions or colors; a motion review may expose an angle or timing; a camera review may expose framing; delivery may ask about format. The request must enumerate the actual fields and ranges in every case.

When the request includes references, pose checkpoints or diagnostic findings, the page provides direct comparison/location controls. A finding selects its recorded frame, camera and first object; it describes the frozen source and does not update itself as the user changes parameters. The agent may also permit point marking, two-point measurement, isolation or X-ray for selected objects. These inspection tools change the view or attach feedback, never the source model. Procedural distances can display the project's units; native GLB measurements remain preview units. Both are unverified preview annotations. See [review.md](review.md) for the evidence and inspection schemas.

Measurement is a guided A/B operation: the persistent in-canvas hint asks for A, confirms A while asking for B, then reports the distance. High-contrast endpoint markers, a double-stroked screen line and a distance label remain legible over light or dark model surfaces. The line tracks the world-space points as the camera moves; it does not claim that an occluded surface is available for picking. An out-of-scope foreground surface cannot be bypassed to annotate a hidden object. Unsuccessful picks explain which surface is required and preserve any existing A point. Measure again or a third valid point begins a new pair; Escape exits the tool and clears samples. Frame, geometry and comparison changes invalidate samples as before.

Point marking and measurement start with **Snap** enabled. The cursor previews nearby eligible vertices, crease edges and view-dependent silhouette edges from the actual geometry displayed in the browser. Coplanar triangulation diagonals are excluded. Candidate feedback distinguishes a vertex, an edge and an ordinary surface point before confirmation. Snapping respects the current camera, visible occluders and the request's permitted objects; it cannot select through an out-of-scope foreground surface. Turning Snap off uses ordinary surface picking and preserves any existing A point.

Deformed meshes, instanced parts and geometry that exceeds the supported complexity limit fall back to surface points, with a visible fallback label and an explanatory tooltip. These features describe the preview mesh, not analytic CAD curves or solid boundaries. They do not establish CAD-level dimensional accuracy, physical calibration or equivalence to final Blender geometry. Measurements retain the unit and verification limits described above. Snap candidates and settings remain viewing state; feedback keeps the supported object ID, local-coordinate and world-coordinate point fields without adding snap metadata.

With no current request, the page says there is nothing to adjust and remains a read-only preview. During a request, the user can compare with the original, reset proposed values, add a note, then confirm or ask for further revision. Submitting locks that response and preserves its values, exact changes and location. It does **not** save the candidate into `project.json` or launch a render. The agent reads and validates the feedback before applying confirmed changes. See [the review contract and commands](review.md).

The page distinguishes feedback saved locally from a result handled by the agent. A live agent wait is temporary; after the agent's turn ends, the submission stays on disk and the user returns to the current task to continue. A link back to the task navigates there; it does not silently submit a message or start another agent.

## Existing Blender assets

The same review workflow can use a project that references a `.blend`. Native discovery reads objects, materials, cameras, animation and external dependencies with embedded scripts disabled. The original `.blend` is preserved; final builds use a separate generated file. A usable scene camera and available dependencies are required.

The browser uses an animated GLB exported from the original scene, then applies supported `source.overrides` after animation evaluation. Removing an override can reveal the original animation again. Supported native overrides include eligible object transforms, simple Principled material values and camera properties. Native mesh dimensions and keyframe authoring remain Blender work. A review can bind only to permitted existing project leaves; prepare any required override structure in the project before creating the request. Read [project-format.md](project-format.md) for exact restrictions.

Constraints, drivers, NLA, linked textures, parent inverses and delta transforms can make a native property unsuitable for direct overrides. Prepare or bake the required behavior in Blender when needed. Arbitrary shaders, physics, compositor graphs and interpolation are not reproduced by the browser; final evidence comes from Blender stills and verified videos.

## Explicit authoring access

For a user who explicitly requests full authoring controls, start the server with `animation.py editor PROJECT --authoring --open` and use `/authoring`. Enabling this mode provides the earlier object tree, transform/material/camera panels, timeline, save and production controls. Ordinary guided reviews do not need this mode. The default server rejects arbitrary project-save/new/open/import mutations.

In authoring mode, the browser and CLI share `project.json`. Changes remain in browser memory until Save or Ctrl+S; preview/render actions save first. Undo/redo changes the current parameters and must be saved to persist. Recovery data belongs to the matching project and revision. Each save validates the schema, checks the active project path and disk revision, and archives the previous JSON in `.animation/revisions`; conflicts are rejected. The server serializes its own Blender jobs, but does not schedule independently launched CLI jobs or other servers.

Select a scene object or use viewport controls to move/rotate/scale it. W/E/R switch transform tools; project-camera and free-orbit views are available. Procedural transform poses can be recorded at source frames. Shot duration changes sample or repeat native event frames; they do not invent new interpolated poses. Native import creates a new project referencing the source asset. These controls are for authoring; do not expose them as a prerequisite for a user's scoped review.
